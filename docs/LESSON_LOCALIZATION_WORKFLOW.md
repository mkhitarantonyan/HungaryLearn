# Обновление уроков и локализаций

Этот документ — единственная рабочая инструкция для правок уроков и переводов. Разовые отчёты, repair-скрипты, dry-run output и резервные копии в репозиторий не добавляются.

## Где находится источник истины

- Структура и русский текст урока: `src/data/lessons/lesson<N>.ts`.
- Полные таблицы переводов: `src/i18n/lessonTranslations.en.json` и `src/i18n/lessonTranslations.es.json`.
- Публичные подмножества для бесплатной части: `src/i18n/lessonTranslations.public.en.json` и `src/i18n/lessonTranslations.public.es.json`.
- Механизм подстановки текста: `src/i18n/lessonContent.ts` и `src/i18n/index.tsx`.
- Проверки качества: `scripts/audit-localization.ts`, `scripts/audit-lesson-translation-quality.ts` и тесты в `tests/`.

Ключ таблицы перевода — точная русская строка. Одинаковая строка может использоваться в нескольких уроках, поэтому изменение общего ключа влияет сразу на все его вхождения.

## Порядок работы над одним уроком

1. Зафиксировать чистую точку возврата отдельным коммитом или веткой. `.bak` для отката не создавать.
2. Собрать все видимые ученику русские фрагменты выбранного урока: заголовки, объяснения, примеры, задания, варианты ответов, quiz, vocabulary и activities.
3. Найти общие ключи, которые уже используются в завершённых уроках. Не менять их без повторной проверки всех потребителей; при различии смысла сначала сделать исходную русскую строку однозначной.
4. Проверить перевод в двух проходах:
   - точность: смысл, грамматика, терминология, плейсхолдеры, HTML-разметка и венгерские примеры;
   - методика: естественная формулировка задания, соответствие уровню, отсутствие ложных правил и понятная связь примера с объяснением.
5. Сначала выполнить dry run разового преобразования. В отчёте должны быть: число исходных фрагментов, число правок, защищённые общие ключи, отсутствующие ключи, оставшиеся русские learner-facing значения и blocker-паттерны.
6. Применять правки только при нулевом числе отсутствующих ключей и критических blocker-паттернов. Разовый скрипт после применения удалить; повторяемую проверку оформить как постоянный скрипт с тестом и npm-командой.
7. Пересобрать публичные подмножества:

```powershell
npm run generate:lesson-translations
npm run audit:lesson-translations
```

Генератор нельзя запускать при пустой, обрезанной или невалидной полной таблице. После генерации оба `lessonTranslations.public.*.json` должны быть валидным непустым JSON.

8. Запустить проверки урока и локализации:

```powershell
npm run audit:localization
npm run validate:lessons
npm run validate:vocabulary
npm run validate:listening
npm run verify:audio
npm test
npm run lint
npm run build
```

Если изменился только один урок, сначала полезно запустить относящийся к нему тест через `npx tsx --test tests/<test-file>.test.ts`, но перед коммитом всё равно выполняется полный набор.

9. Проверить diff: в нём должны быть только выбранный урок, необходимые таблицы/генерируемые файлы и осмысленные тесты. Не коммитить логи, скриншоты, архивы, dry-run output и копии файлов.

## Правила для всех 28 уроков

- Обрабатывать уроки последовательно и фиксировать завершённый номер вне исходного кода — в задаче или истории коммитов.
- После каждого урока запускать специализированный тест и аудит локализации.
- После серии уроков повторно проверять общие ключи: поздняя правка не должна ухудшить уже завершённые уроки.
- Не заменять текущую локальную таблицу переводов таблицей из ZIP, старой ветки или удалённого baseline. Такие источники допустимы только для сравнения отдельных значений.
- Сохранять венгерский текст, ID, placeholders, теги и структуру exercises без изменений, если задача явно не включает правку исходного урока.
- Машинный перевод считать черновиком; итог всегда проходит языковую и педагогическую редактуру.

## Когда меняется аудио

Любое изменение озвучиваемого текста требует проверки соответствующего MP3. Актуальный порядок замены записи, регенерации manifest и аудита описан в `docs/AUDIO_MAINTENANCE.md`. Narration нельзя подменять browser TTS, а listening-запись — озвучкой текста слайда.

## Хранение технических материалов

- Git-коммиты и ветки заменяют `.bak`, `.old` и копии `file-final-final`.
- В `docs/` хранятся только действующие спецификации, процедуры и контракты.
- Исторический отчёт удаляется после переноса ещё актуальных действий в рабочую инструкцию или issue.
- Генерируемые локальные артефакты находятся вне репозитория либо в игнорируемом `artifacts/` и удаляются после проверки.
- Секреты, локальные `.env`, credentials и служебные дампы не коммитятся.
